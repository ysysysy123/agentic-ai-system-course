01先分清谁负责什么

“用户”是使用系统的人；“需求”是他希望系统完成的事。“请解释语音助手”就是一个需求。下面四个词，描述了系统如何承接这个需求。

PROGRAM · 程序

让电脑执行的步骤

例如：接收名字、拼出问候、显示问候。写在文件里的指令叫源码；启动程序后，电脑才开始执行这些步骤。

PROJECT · 项目

围绕目标组织的材料

源码、配置、文档、测试一起构成项目。配置选择运行选项，测试检查行为。Deskbot 包括语音服务、网页和机器人等部分。

CLIENT / SERVER · 客户端与服务端

发起请求，与处理请求

浏览器页面采集输入、展示或播放结果；语音服务接收请求、组织处理并返回结果。两者可以都运行在同一台电脑上。

LANGUAGE MODEL · 语言模型

根据文字生成文字

大语言模型常写作 LLM。它接收当前问题和程序准备的相关信息，生成回答，也可能提出工具请求。模型可以在本机或远程服务运行。

源码上传到 GitHub，表示文件已保存到远程仓库。真正使用语音助手，还需要启动相应程序并让模型服务可用。

输入

用户说出的声音，或输入的文字。

处理

接收、转写、准备上下文、回答，以及合成声音。

输出

用户能看到的文字、听到的声音，或执行完成的工具结果。

02跟着一句话，走过整条链路

先看语音问答。下方每个方块是一项职责。点击“下一步”观察数据怎样变化，也可以直接点某个环节。

本地教学模拟

输入：“请简单解释什么是语音助手。”

查看已经经过的消息与数据

    演示中的文字、工具结果都是固定示例。这里不会连接模型、打开麦克风或摄像头，也不会向机器人发送指令。

    三个缩写，一次讲清

    VAD · 语音活动检测
    判断一段声音里是否有说话，帮助系统确定一轮发言何时结束。手动停止录音也能结束输入。
    ASR · 自动语音识别
    把声音转成文字。如果这里把问题识别错了，后面的模型可能收到错误的问题。
    TTS · 文字转语音
    把回答文字转换成声音数据。声音还要被发送、接收和播放，用户才真正听见。

    上下文是本次回答可以参考的信息，例如刚才说过的话、助手的回答方式和相关偏好。模型能参考哪些历史，需要程序准备并提供。

    本课按职责画图。真实浏览器链路中，一部分声音判断发生在测试桥，一部分处理发生在语音会话；具体分工、声音编码和队列将在后面逐步拆解。

    03改变一个条件，看看哪些环节受影响

    直接输入文字，会发生什么？

    回到上方，选择“文字提问并朗读”。采集声音、判断录音结束、声音转文字都被跳过；程序继续准备上下文、生成回答，再做语音合成和播放。

    原因：问题已经以文字形式到达，程序可以直接使用。

    有回答文字，却听不到声音？

    这次文字处理已有可见结果。接下来检查 TTS 是否产生声音、服务端是否发送、浏览器是否接收和播放，以及音量与输出设备。

    定位方法：沿数据经过的节点收集证据，逐步缩小范围。

    同一个方法，也能用来读代码

    对每个函数问三件事：它接收什么，做了什么，返回什么。等学到代码，我们会用同样的方法追踪真实变量和调用。

    04当助手需要采取行动

    换一个任务：“查询一下设备状态。”回答需要来自设备的信息。工具是程序提供的一项具体操作，例如查询状态、拍照、调整音量。工具有输入，也会返回执行结果。

    当模型能围绕目标提出工具请求，再根据工具结果决定下一步，就体现了 Agent 的核心机制。下面展示这种模型工具循环的简化路径。

    查询设备状态 · 工具循环示意模拟工具已就绪

    查看已经经过的工具消息
      对照当前 Deskbot 的实际路径

      默认配置使用普通语言模型对话；开启 MCP 后，可以使用现有摄像头与设备工具后端。MCP 是连接和调用工具的一类协议，后面单独学习。

      明确的拍照、运动、停止请求还有程序直接处理的路径；因此，并非每个操作都要先让文字模型选择工具。真实设备返回“收到指令”，也需要与“实际动作完成”区分。

      第一课先记住：模型可以提出请求；程序执行工具；执行结果给后续回答提供依据。用户看到“已经完成”时，可以继续查对应的调用与结果。

      项目文件与职责 · 路径相对 Deskbot/server/voice
      文件负责什么
      run.py启动语音服务。
      local_test.py启动浏览器测试页和桥接服务。
      src/voice_server/app.py组装语音、模型、记忆与工具组件。
      src/voice_server/session.py组织一轮输入、回答、声音发送和打断。
      src/voice_server/dialogue.py约定对话后端接收什么、输出什么。
      src/voice_server/camera_dialogue.py直接指令处理，以及模型工具循环。
      src/voice_server/providers/接入语音检测、识别、模型与合成。
      src/voice_server/memory/存取对话、摘要与用户偏好。
      local_test/浏览器的页面、交互与音频处理。

      “组件”是一项职责对应的程序部分；“接口”是不同部分约定怎样传入和返回信息。打开测试网页后，仍需语音服务和相应模型能力就绪，才能完成真实对话。
