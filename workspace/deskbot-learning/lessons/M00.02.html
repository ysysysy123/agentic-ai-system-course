01问题引入：编辑器、终端和 Python 解释器到底是谁？

零基础第一次写代码最容易犯的一个迷糊，就是把本该敲在黑色终端窗口里的命令（比如 cd 或 python3 xxx.py），写进了 .py 代码文件里，结果一运行就报 SyntaxError（语法错误）。

一句话防混铁律：凡是像 pwd、ls、cd、pytest、git 这样的操作指令，永远敲在终端（Terminal）里；.py 文件里只写给 Python 翻译官读的语法。
写信 vs 跑腿送信（分清三个窗口）
  • 源码文件（.py 纯文本文件）：就像一张写满步骤说明的纸，本身是静止的，放在硬盘上不会自己动。
  • Python 解释器（python3 程序）：真正干活的“翻译执行官”。它从上到下逐行读你的 .py 文件，把指令翻译给电脑执行。
  • 终端（Terminal / Shell）：你向操作系统发号施令的对讲机。你在终端里敲 python3 task.py，意思就是喊操作系统：“请叫醒 Python 翻译官，去执行当前文件夹下的 task.py！”

必须认识的 4 个终端高频词与虚拟环境（.venv）

命令 / 概念干什么用？在 Deskbot 项目里的真实意义
pwd打印当前所在目录（Print Working Directory）报错“找不到 config.yaml”时，第一步先敲 pwd 看自己站在哪个文件夹！
ls / cd 路径列出当前目录文件 / 切换到另一个目录相对路径（不以 / 开头）永远相对于你当前 pwd 站立的位置计算。
退出码 (Exit Code)程序结束时交回给系统的整数：0 代表成功，非 0 代表出错run.py 里写的 raise SystemExit(main()) 就是在向系统汇报退出码（配置错误返回 2）。
.venv 虚拟环境给单个项目单独准备的“独立工具箱文件夹”Deskbot/server/voice/.venv 装好了专属的 Python 3.11 和 pytest，不会和电脑上别的项目打架。

02零基础拆桥：变量、5 种基本类型与 f-string

打开任何 Python 文件，最基础的砖块只有三样：给数据贴标签（变量）、区分数据长什么样（类型）、把数据拼成句子打印出来（f-string）：

1 · 极简日常小例子（零前置） 
# 井号 # 后面全是给人类看的注释，Python 会直接跳过
name = "小桌"          # str 字符串：文字，必须用引号包起来
port = 8000           # int 整数：不加引号，能做加减乘除
threshold = 0.5       # float 小数：带小数点的数字
mcp_on = False        # bool 布尔值：只有 True(真) 和 False(假)，首字母大写！
err = None            # None：专门表示“空 / 暂时没有值”

# 字符串前加字母 f，花括号 {变量名} 就会被自动替换成变量的值
print(f"助手 {name} 监听端口：{port}，工具开启：{mcp_on}")

特别小心等号 =：在代码里 port = 8000 不是数学里的“相等”，而是“把右边的 8000 存进左边叫 port 的标签盒里”（判断相等以后用双等号 ==）。

2 · Deskbot 真实源码对照 
    config = load_config(args.config)
    print(f"浏览器测试页：http://{config.local_test.host}:{config.local_test.port}/")
    print("测试页连接真实语音服务；请另开终端运行 run.py。Ctrl+C 停止测试页。")

看第 20 行：f"http://{...}:{...}/" 把配置里的主机地址（字符串 "127.0.0.1"）和端口号（整数 8006）拼成了一条可直接点击的网址！

新手头号陷阱："20"（字符串）不等于 20（整数）！

在环境变量和网页输入框里，读进来的数字默认全带引号（如 "20"）。"20" + "5" 会拼成字符串 "205"；而 20 + "5" 会直接触发 TypeError 崩溃！算数学前必须确认它是 int 或用 int("20") 转换。

04真实源码走读：读懂 run.py、local_test.py 与依赖清单

现在你已经能够彻底看懂 Deskbot 根目录下的启动入口文件了！点击切换下方标签，再点击右侧编号卡片看每行代码到底在干什么：

"""Start the voice server from this directory without setting PYTHONPATH."""

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent / "src"))

from voice_server.__main__ import main


if __name__ == "__main__":
    raise SystemExit(main())
  1. 三引号文档字符串：文件顶部的说明文字，告诉开发者这个脚本用来免配置直接启动语音服务。
  2. 用 __file__ 锁定 src 目录：Path(__file__).resolve().parent 拿到 run.py 所在的文件夹，拼上 / "src" 后塞进模块搜索列表第 0 号位——这样不管你在哪个目录调用 run.py，第 8 行都能找到 voice_server！
  3. 直接运行入口与退出码：当直接运行 python run.py 时执行 main()，并把它的整数返回值作为进程退出码交给系统（0 正常，2 配置错）。
def main() -> None:
    parser = argparse.ArgumentParser(description="Deskbot 本地语音测试页面")
    parser.add_argument("--config", type=Path, default=Path(__file__).with_name("config.yaml"))
    args = parser.parse_args()

    from aiohttp import web
    from voice_server.config import load_config
    from voice_server.local_testing import create_local_test_app

    config = load_config(args.config)
    print(f"浏览器测试页：http://{config.local_test.host}:{config.local_test.port}/")
    print("测试页连接真实语音服务；请另开终端运行 run.py。Ctrl+C 停止测试页。")
    web.run_app(create_local_test_app(config), host=config.local_test.host, port=config.local_test.port, access_log=None)
  1. 对比细节（非常妙！）：Path(__file__).with_name("config.yaml") 表示“找和 local_test.py 同文件夹下的 config.yaml”，所以哪怕你在别的目录运行它也不会找错默认配置！
  2. 双进程关系明示：打印出 8006 测试页地址，并明确提醒你“测试页本身只是桥梁，真实对话需另开终端跑 run.py”。

06本课浓缩与工程好习惯

三句话记住本课精髓
  • 分清战场：cd / ls / python3 是敲给终端的命令；变量、print、import 才是写进 .py 的代码。
  • 路径防坑：普通相对路径跟着终端 pwd 跑；想稳稳找到脚本同级资源，用 Path(__file__).resolve().parent。
  • 类型敏感：永远留意手里拿的是文本 str、数字 int/float、开关 bool 还是空值 None。
工程排查思维 · 面试加分表达

「遇到路径或模块导入报错时，我不会盲目改环境变量，而是先核查两点：一是进程启动时的当前工作目录（CWD），二是代码里的相对路径究竟是基于 CWD 还是基于 Path(__file__).resolve() 锚定的——例如在 Deskbot 的入口脚本中，src 搜索路径就是通过 __file__ 锚定的，避免了跨目录启动找不到包的问题。」
